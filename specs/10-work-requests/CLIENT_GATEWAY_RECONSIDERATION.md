# Client Gateway & Reconsideration

After the last intermediate route occurrence completes, the system activates the derived Originating Division final-review occurrence. Only the exact bound Responsible Originating Division Lead, subject to the applicable permission/scope/context checks, may exercise the originating-gateway responsibility to compose C1's immutable exact-version package and submit it to the Client. Another Lead in that Division does not inherit this Work Request authority. Intermediate Divisions never become final Client gateways.

C1 remains authoritative for package snapshots, Client/ClientContact linkage, external authorization, `ACCEPT`, `REJECT`, and `REQUEST_REVISION` decision history, and resubmission package numbering. Client revision enters the exact Responsible Originating Division Lead's handling. That Lead resolves the actual source internally or creates a cross-Division formal revision as defined in [Revision & Resume](REVISION_AND_RESUME.md); correction always returns to Originating Division final review before Client resubmission.

Client rejection is normally terminal. Persist a tenant-qualified, immutable reconsideration request and decision history with one uniqueness boundary per Work Request. Only the exact Responsible Originating Division Lead may request it once while rejected. The exact authorized ClientContact may accept or deny it once. Denial remains terminal `REJECTED`; acceptance reopens the documented correction path, which ultimately returns to Originating final review and a new immutable C1 package. Neither reconsideration nor Client request alone increments formal document revision.
